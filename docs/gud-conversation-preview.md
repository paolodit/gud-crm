# GUD Actions + Conversation preview

The global **Talk to GUD** button opens a compact panel that persists between CRM pages. Opt in to sending the conversation and relevant record details to OpenAI, then type or start voice. The older single-record voice review remains available.

## First workflows

- Create/update a sales lead with company/contact details, owner, offer, value, priority, temperature, probability, expected close, outreach angle, company fit/qualification, a typed/outcome-dated touchpoint and scheduled follow-up.
- Find/open an existing lead or project, prepare updates, and switch clients without discarding earlier drafts.
- Add/complete sales follow-ups and project checklist items. Project checklist items do not have independent due dates.
- Create/update live projects with value, owner, offer, stage, milestone/date, appended notes and multiple separate checklist items.
- Create, search, read and update your own private Thoughts with title/body, colour, existing/new category and real checklist items. Shared `all` search excludes Thoughts; personal Thoughts remain disabled on the shared public Demo.
- Create/read/refine Marketing Ideas with audience, problem/change, evidence, source URLs, progress and service angles. “Talk it through” starts guided refinement; a completely new service does not require an existing offer.
- Create/update Targets, company research and contact details, and link targets to marketing ideas, services/products, or both. Idea associations are organisation-validated and stored in existing opportunity metadata; no migration is needed.
- Navigate to Marketing Ideas, Targets, Reports and Video guides. Page-owned controls expose filters, selection, research handoff, export/import entry points and existing editors. Reports expose current metrics; guides can be searched, filtered and opened on YouTube (subject to browser popup controls).
- Close a clean record/editor pop-up by asking GUD. Unsaved manual edits are protected.

Try: “Sarah at Acme wants a £5,000 website before Christmas. Follow up next Thursday at ten.” GUD should look for an existing match, prepare the lead and ask for any genuinely missing offer/identity details. Review the visible fields, then say/type **“Save changes”** or click the button. Both GPT-Live and Realtime support explicit voice saves. “Add a note and save changes” first stages the addition, then advances approval only to versions returned by that request. A successful save receives **“Saved. All Gud.”** Unsaved or failed work gets an explicit draft/error message instead.

## Safety contract

`src/lib/gud-actions/contract.ts` defines allowlisted navigation, scoped search/read, staging, revision, guarded saving, close-record and finishing tools. `save_changes` cannot authorize itself: it requires an independent, explicit user Save command bound to the visible draft IDs/versions. Realtime transcription is correlated with the speech-start item and may arrive after a tool call; GUD waits briefly for it. Old, negated, conditional or vague requests never count. A clear typed Save goes directly through the same guarded transaction without another model request. Both transports require the signed-in member and matching Origin; actor/organisation IDs are never taken from model arguments. Impersonation and non-PostgreSQL workspaces are excluded.

The private `gud_action_drafts` table scopes every read/write by organisation and owner. Drafts expire after 24 hours and survive navigation/reconnection. Manual changes use draft versions. Existing-record fingerprints reject a stale save. The final button commits the reviewed draft versions and their receipts in one PostgreSQL transaction; retrying a saved draft returns its receipt rather than creating another record. Existing service transactions join the outer transaction using request-local AsyncLocalStorage. Failure in a later draft rolls the bundle back.

Tool fields are partial patches: unused fields can be omitted or null (both mean unchanged). Every supplied value remains validated and unknown keys are rejected. Invalid-call feedback names only safe contract fields so GUD can correct its arguments without exposing record values. Project progress updates use the opened project's tasks and milestone; moving to a matching task does not implicitly complete earlier tasks.

Destructive page controls open their existing confirmation UI; they do not silently delete or archive. There are no direct conversation delete/archive tools, terminal won/lost sales moves, outbound messages, arbitrary database actions, invoice operations, whole-database provider upload, or autonomous background work. Private Thought text is not copied into shared audit events.

## Operations and limits

- `GUD_CONVERSATION_ENABLED=false` disables the preview without removing classic voice.
- Uses existing AI connection/key and organisation AI-enabled setting. Keys stay server-side.
- `GUD_VOICE_ADAPTER=live` is the new default, using exactly `gpt-live-1`. Set `GUD_VOICE_ADAPTER=realtime` and restart to roll back; `GUD_REALTIME_MODEL` remains `gpt-realtime-2.1`. Typed conversation and Live's delegated reasoning use the existing `AI_MODEL` (default `gpt-5.6-luna`). There is no automatic paid retry/fallback.
- Live uses WebRTC through server-proxied JSON `POST /v1/live/sessions`; Realtime retains the multipart `/v1/realtime/calls` handshake. Keys and startup configuration stay server-side; every CRM tool call returns to the authenticated server.
- Live's short conversation/delegation prompt is separate from the full CRM backend prompt. Tools use Responses delegation with sequential calls. The client waits for `session.started`, collects complete function items by delegation/response ID, returns every result with `response.item.create`, then continues with `response.create`. An empty terminal `response.output` does not lose tool calls. Failed, duplicate and late responses cannot execute new actions.
- Live captions preserve input/output fragments independently, including overlap. Display grouping is not a completed utterance or playback confirmation. User captions provide an independent explicit-command gate for a subsequent save tool request: assistant captions and model arguments cannot provide approval. Captions never trigger a save by themselves. The server additionally checks freshness, exact draft IDs/versions and record fingerprints. Corrections revoke the pending command; conditional/negated commands fail closed. An additive save must first receive a draft-mutation receipt. No silence timer auto-saves.
- Live microphone glow uses a local level meter on the already-authorized stream; there is no second capture or upload. Tracks stop immediately on End; the channel remains briefly for `session.closed` final usage, with authenticated provider hangup as backstop. Live has no audio-playback-done event: sign-off uses a bounded 15-second grace period, cancelled if the user speaks again, without claiming the sign-off was heard.
- Live duration is recorded as the maximum cumulative seconds observed, not summed. Backend tokens are separate. Both are unverified client telemetry, not a billing ledger. Provider IDs use an application-owned `gud-live:` discriminator so hangup targets the correct API after a config change; legacy untagged IDs remain Realtime. No database migration is required.
- Live sessions use `store: false`; no recording/forking is enabled. Official pricing is $0.05/session-minute, billed per second, plus backend model/tool costs. WebRTC initialization bills 15 seconds credited against running duration: [pricing](https://developers.openai.com/api/docs/models/gpt-live-1), [WebRTC setup](https://developers.openai.com/api/docs/guides/voice-webrtc?api=live). Account access and real speech quality require a separately authorized live test.
- One voice connection per session; ten-minute session limit, two-minute client idle timeout, explicit mic pause/end, and best-effort server provider hangup timer. A server restart loses the in-memory hangup timer, so this is not a guaranteed monetary cap.
- Existing `AI_RATE_LIMIT` applies to conversation starts per member per 15 minutes. Sessions allow at most 120 server actions; model responses are output-bounded. Client-reported realtime token usage is accumulated and labelled as unverified—not a billing ledger. Typed usage is not yet reported in the UI.
- Closing the panel ends voice and keeps unfinished drafts; cancelling clears the draft fields. Expired drafts are unavailable but retained in the private table pending a retention/cleanup policy. Transcripts are kept in the browser component, not a new transcript database.
- A fresh voice connection restores drafts and page context, not a transcript of previous voice sessions. Finish/close never implies permission to save.
- End stops microphone tracks immediately, even while a response is pending. Late responses cannot navigate or speak; any draft already staged is reloaded for review. Lost voice connections close the provider session before reconnecting. Realtime sign-off waits for its own audio to drain, not the preceding response; Live uses the grace period described above. Speaking again interrupts sign-off.
- The Talk to GUD launcher glows while the microphone is live and pulses when speech is detected, including with the panel minimised. Muting or disconnecting removes the glow. Reduced-motion preferences retain a steady glow. Realtime uses speech events; Live uses the local level meter. Neither makes another provider request.
- Manual draft edits are acknowledged independently, so an interrupted second edit can retry without invalidating a successful first edit. An empty amount is never silently converted to £0. The Save button pauses microphone input only during commit, then restores its previous state. In-flight responses from before the manual save are rejected using a review epoch. Both voice transports continue after spoken saves. Identical adjacent confirmation messages are deduplicated. Completing an action or a save does not end the conversation. The main launcher resumes a paused mic; on/off/paused labels and green/grey/amber panel states distinguish recording clearly.
- Thought date sorting is a newest-first column display only: Free sort restores the saved manual positions. Categories are saved on private notes, not a shared taxonomy. The category picker explicitly offers existing categories and creation; quick colour controls and swatches are square. The date-sort hint no longer shifts the toolbar. New notes try nearby measured/estimated card edges before falling back to the grid. Editor backdrop clicks save valid content and close only on success; errors retain the editor. The heading remains screen-reader accessible without a visible redundant label. Classic capture starts on the mic click, including Thoughts, new projects and opportunities.

Roll out using `npm run release:all -- --ref <full-sha> --targets demo,refresh`. The target selector allows only canary-order prefixes; omitting it retains the existing all-three rollout. The same guarded image, backups, health checks and record-retention checks apply. HSM is excluded from this preview rollout.

## Verification

Contract tests check the tool boundary, field scopes and honest sign-offs. HTTP tests cover Origin, authentication, actor spoofing, streamed byte limits and exception privacy. The dedicated disposable-PostgreSQL suite covers draft ownership, create-lead contents, idempotent saves, stale edits, concurrent transaction isolation, full rollback, project tasks, Thought privacy and cancellation during provider/voice connection requests. CI additionally exercises the panel against isolated text and WebRTC transport fixtures, including failed-save/retry, partial manual edits, navigation persistence, mobile bounds, delayed tool responses, audio sign-off, immediate mic stop and reconnecting. The annotation UI fixture also checks backdrop saving, first-click speech capture, marketing progress controls and persisted target/idea links. Fixtures use no physical microphone or live OpenAI calls. A real microphone conversation still needs an interactive browser test with microphone permission and a model-enabled OpenAI project.
